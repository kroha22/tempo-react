# Мой план — свободная практика

В детском оформлении публичной GitHub Pages демоверсии раздел «Уроки» открывает пять тематических блоков и 23 занятия: 14 существующих коротких уроков грамматики, 7 существующих словарных наборов и 2 интерактивных урока. Содержание не копируется: используются прежние IDs, формы, примеры и проверки. Каталог и свободная практика остаются доступны. Новых уроков канонического Route этот модуль не создаёт.

Счётчик означает число выполненных занятий, а не оценку владения языком. Открытие сохраняет только последний выбранный шаг. Грамматическое занятие засчитывается после правильного ответа; ошибка разрешает повторную попытку. Словарное — после ввода и проверки всех слов. Интерактивное — после всех проверочных вопросов и перехода к итогу. Ошибки и подсказки дают отметку «стоит повторить»; последующее выполнение без помощи снимает её. Повторение не увеличивает общий счётчик.

План рекомендует незавершённое занятие, сохраняет завершённые и позволяет открывать любой блок. После перезагрузки виден план и кнопка продолжения последнего незавершённого занятия; ответы и внутренняя позиция упражнения не сохраняются, поэтому само незавершённое занятие начинается заново.

## Граница хранения

`PracticePlanProvider` принимает порт хранения. Браузерный адаптер подключён **только в `github-pages/Demo.tsx`**, под отдельным ключом `tempo-react:github-pages:practice-plan:v1`. Участие в свободной практике и из плана, и из каталога обновляет одну запись. Записи не содержат имени, идентификатора пользователя или введённых ответов. Интерфейс прямо указывает, что сохранение действует в текущем браузере; синхронизации устройств нет.

Это дополнительный счётчик статической демоверсии. Он не читает и не заменяет `lesson_progress`, `learning_events`, API/D1, Can-Do результаты, SRS или прогресс карточек. Серверный Learning Home и Lesson Engine продолжают использовать авторизованный API/D1. В серверной версии браузерный адаптер плана не подключён; для долговременного общего плана нужен отдельный серверный адаптер и авторизация, а не автоматический fallback в localStorage.

Хранение проверяется до изменения счётчика. При сбое остаётся явное сообщение и повтор записи. Ошибочные/неподдерживаемые данные не заменяются пустым планом. Существующие IDs и записи новых ревизий сохраняются; число завершений считается по известным занятиям текущей ревизии. Другой вкладке передаются изменения через `storage`; перед записью перечитываются и объединяются сохранённые завершения. Это не транзакционная синхронизация между устройствами.

`model.ts` содержит чистые правила порядка, счётчика, ревизий, объединения и проверки данных. Схема D1 не меняется, миграция не требуется.

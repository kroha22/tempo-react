# Подготовка реализации

Статус: исходный чек-лист подготовки. Взрослые U18–U23 реализованы; актуальное покрытие и ограничения — [в RUNTIME](RUNTIME.md). Нормализация и подключение словаря выполнены: [VOCABULARY](VOCABULARY.md). Пункты ниже сохранены как требования и не являются списком оставшейся работы. [План курса](README.md).

## Сначала словарь

1. Проверить равенство связей CSV и JSON, охват U01–U54 и дубли.
2. Сохранить исходную связь `unit + stage + pt + ru` и происхождение `adapted_from_book_topic`.
3. Разобрать написания на лемму, часть речи, значение, форму и выражение. `unique_key` исходника не является достаточным ключом значения; заявленное в metadata поле part_of_speech в карточках отсутствует.
4. Для существительных добавить проверенные артикль, род, plural и пример; для глаголов — infinitive, значение и управление; для chunks — цельную строку и смысл.
5. Создать явную карту source row → canonical entity → StudyItem; объединённая сущность сохраняет все sourceRefs. До этого импорт карточек заблокирован редакционно, без изменения D1 и существующей колоды.

## Затем уроки U18–U23

Переиспользовать `features/content/short-grammar-lessons.ts` и существующие упражнения после сверки смысловой эквивалентности. Один quiz в ShortGrammarLesson не представляет весь многофазный сценарий; исходный JSON с `steps` не объявлять LessonFlowDefinition без адаптера.

Для каждого урока подготовить: Can-Do, grammar targets, новые/повторяемые/recognition-only значения; контекст и правило; 6 диагностических, управляемые задания, 5 независимых выходных; подсказки, объяснения distractors, error→remediation; Card Save и ReturnContext. Для U19 нужна модель пересечения событий, а не только timeline_order.

Каждый оцениваемый item имеет один основной диагностический target. Формы берутся из общего resolver, когда он покрывает конструкцию. Входные GA1-U18 и 18-01 остаются source aliases; новые канонические ID выбираются по смыслу, без зависимости от позиции в маршруте. Сначала проверить занятые ID.

Строковые ответы: Unicode NFC, пробелы, регистр и конечная пунктуация нормализуются; диакритика сохраняется. Несколько естественных формулировок перечисляются явно. Свободное письмо не получает ошибку только за отсутствие строки в коротком списке эталонов.

## Проверка перед подключением и выпуском

- Проверка ссылок, ID, лимита новой лексики, ключей и соответствия CSV/JSON.
- Редакторская проверка pt-PT/ru; страницы книги и порядок тем отдельно сверить с PDF. Визуальные отметки не переносить в прогресс.
- Доменная проверка выбора времени и допустимых ответов; ошибки диакритики отдельно от выбора конструкции.
- Production build на поддерживаемой Node; затем desktop и 390×844, клавиатура, доступные альтернативы сценам и сохранение/возобновление через API.
- При изменении схемы D1 — миграция Drizzle; сам план миграции не требует.
- Публикация — отдельный этап после готовности реализованного блока. Этот пакет не меняет сайт и не устанавливает навыки/плагины.

Рекомендации повторения через 1/3/7/14 дней из исходников — педагогическая заметка, не замена текущего чистого SRS-модуля.

# Интервальное повторение Gramática Ativa 1

Реализация: 2026-11-01–02. Взрослый вариант, локальный Worker/D1; без публикации.

Дополнение U04–U11: реестр теперь принимает 388 прежних и новых словарных/урочных StudyItems (375 словарных + 13 остальных выражений U18–U23). ID и расписания прежних карточек не менялись; 16 новых источников описаны [в отчёте блока](U04-U11-IMPLEMENTED.md). На GitHub Pages серверного SRS нет; дальнейшие числа первого этапа ниже сохранены как история реализации.

## Путь ученика

Курс, словарь и раздел Карточки содержат ссылку «Интервальное повторение». Основной путь: `/learning/gramatica-ativa/review`, фильтр урока: `/learning/gramatica-ativa/review/u18`.

В повторение попадают только ранее сохранённые активные StudyItems. Сначала просроченные карточки, затем новые; базовые/первые 40 глаголов имеют пониженный приоритет среди новых. Нужно открыть ответ, затем выбрать «Не знаю», «Сложно», «Помню» или «Легко». До подтверждения сервера карточка и ответ остаются на месте. После подтверждения показываются дата и интервал следующего повторения. При пустой очереди срок проверяется автоматически, не реже раза в минуту, либо кнопкой.

В статическом демо оценки и SRS не подменяются browser storage: доступен словарь, а экран повторения объясняет необходимость серверного Tempo. Детская копия не создана.

## Общий SRS и идентичность

`features/cards/scheduler.ts` остаётся единственным владельцем расчёта: новая чистая `scheduleReviewProgress` выделена из прежней `scheduleReview` без изменения формул. Старая функция вызывает ту же математику с прежним lower-priority flag. Новый сервер также вызывает её. Принадлежащие 1000-глагольной колоде rank/basic остаются отдельными исходными полями: для импортированных глагольных значений приоритет берётся по инфинитиву из существующих метаданных, без выдуманного ранга и смены ID.

Реестр `features/cards/study-review/catalog.ts` содержит 375 StudyItem IDs: 362 нормализованных значения словаря и оставшиеся 13 самостоятельных выражений из ранее созданных U18–U23. Пересечения объединены по прежним StudyItem IDs; grammar chunks не превращаются в новые глаголы.

Ключ расписания — уже существующий `saved_study_items.review_item_id`. Ни `studyItemId`, ни `reviewItemId` не пересоздаются при оценке или фильтрации по уроку. Все связи с 54 уроками и пользовательские source contexts остаются у прежних владельцев. Одна и та же карточка в U18 и U19 имеет одно расписание. Сохранение из ещё одного урока не сбрасывает его.

Старая `flashcard_progress` и все `v0001–v1000` остаются нетронутыми. Sense-specific StudyItems не склеиваются автоматически с широкими карточками частотной колоды. Существующие saved rows не массово перезаписываются: отсутствие SRS-строки означает новую карточку с version 0, а расписание создаётся при первой оценке.

## Хранение и API

Добавочная Drizzle-миграция `drizzle/0002_flippant_photon.sql` сгенерирована через `npm run db:generate`:

- `study_review_progress`: user + reviewItemId, due, interval, ease, repetitions, lapses, lastGrade, reviewedAt, version.
- `study_review_events`: user + clientEventId, StudyItem/reviewItem IDs, grade, expectedVersion и неизменяемый снимок результата. Дополнительная уникальность user + reviewItemId + expectedVersion.

Все прежние определения таблиц в snapshot совпадают с 0001; миграция не изменяет и не копирует их данные. Она применена только к локальной D1 для QA.

`GET /api/study-reviews` возвращает только собственные активные сохранения из поддерживаемого реестра и серверное время. `POST` принимает только studyItemId, clientEventId, grade 0–3 и expectedVersion. Identity определяется существующей серверной auth-границей; userId, due, interval и другие лишние поля отклоняются. Оценка несохранённой/чужой карточки запрещена. Сервер вычисляет дату и весь progress из своего времени и последней сохранённой версии.

Запись выполняется атомарным D1 batch с параметризованными SQL-командами: резервирование события только для текущей версии, затем CAS обновление расписания только для соответствующего события/card/grade. Повтор того же намерения возвращает первоначальный снимок. Изменённые grade/card/version под тем же event ID конфликтуют; два конкурирующих новых события для одной версии не могут оба примениться. Повторная сетевая доставка не увеличивает repetitions/lapses второй раз.

## Клиентские границы

`contracts.ts` — browser-safe Zod DTO; `api.ts` — HTTP с тайм-аутом и проверкой acknowledgement; `model.ts` — очередь и вызов общего SRS; `session.ts` — чистый reducer. `use-study-review.ts` использует существующий TanStack Query scope, держит активную карточку отдельно от refetch и повторяет исходный command без нового event ID. На 409 требуется явная перезагрузка, а не автоматическая переоценка. На 401/403 scope очищает карточку и pending intent. Более старый acknowledgement не понижает уже известную версию cache.

Мутации SRS не изменяют прогресс Lessons, исходный словарь, список сохранений или source contexts. Переворот сам по себе не создаёт оценку.

## Проверка и границы

- Node 22.23.2; доменные тесты сравнивают общий расчёт, сохранность basic/frequency политики, очередь по срокам/урокам, неизменность неотправленной попытки и строгий payload.
- Компонентные тесты: double click, ожидание acknowledgement, network retry того же command, 409 без автоповтора, очистка на 401, отсутствие browser-only SRS в статическом демо.
- Worker/D1: все четыре оценки, повтор и изменённый replay, версии, шесть конкурентных дублей, конкурентные разные grades, коллизия event ID между разными карточками, первая оценка только после Card Save, сохранность savedAt/источников/прежнего review progress, изоляция пользователей, basic-verb interval. Вместе с прежними integration suites — 6 тестов, успешно.
- Browser: 390×844, переворот Space и оценка; reload и переход U18→U19 сохраняют одно расписание. Desktop 1280×900: «Не знаю» сохраняет минутный интервал. Скриншоты в output/playwright; горизонтального overflow в проверенных состояниях нет.
- Автоматический возврат после «Не знаю» подтверждён без перезагрузки: карточка снова появилась примерно через 61 секунду. Статический production bundle показал объяснение отсутствия серверного SRS и ссылку на словарь; кнопок оценки там нет. Сохраняется ранее известный 404 старой обложки `/ser-guide-adult.webp`, не используемой новым экраном.
- Независимая проверка алгоритма обучения, физическая экранная клавиатура, Safari и реальный screen reader не выполнялись. Успешный SRS self-rating не является доказательством grammar Can-Do.

Финальный `npm run check` на Node 22.23.2 прошёл: lint, TypeScript, 105 domain/contract, 214 component и 20 server tests, production build. Прогон повторён после тайм-аутов во время длительной паузы системы; в итоговом прогоне ошибок нет. `npm run build:pages` также успешно; предупреждения bundler о размере общего chunk и существующем смешанном static/dynamic import остаются.

Схема и сгенерированная миграция зафиксированы отдельным коммитом `3e1b633` (`Add saved-card SRS progress and event tables`), как требует AGENTS.md. Он содержит только db/schema.ts, SQL, snapshot и journal. Остальной текущий код остаётся в рабочем дереве. Push, remote D1 и production не изменялись; посторонние рабочие изменения сохранены.
